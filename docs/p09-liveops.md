# P09 LiveOps｜内容节奏与版本运营

> 展示《灯谶》如何从一次性 Demo 转为可持续迭代的产品运营框架

---

## 版本运营原则

- 每个版本只强化一个玩家可感知的主题，避免同时改写过多规则。
- 运营内容应嵌入既有祭灯、遗影、命簿节点，避免额外菜单破坏沉浸。
- 每次投放都绑定一个观察问题：玩家是否看见、理解、使用并愿意再次进入该内容。

## 运营节奏：一局内与一局外

### 局内节奏

首分钟建立战斗理解 → 中段用祭灯把玩家从割草行为拉入目标决策 → 末段用命簿收束本局立场。

### 局外节奏

以版本档案、人物证词与命簿结局作为可复用的传播素材，承接公告、社群讨论、回流提醒与内容预告。

---

## 内容运营 SOP

1. **提出假设**：例如"玩家是否会为了额外灯焰主动进入高风险灯界"。
2. **配置投放**：在遗愿池或证词卡中新增一个限定选择，不改动基础战斗框架。
3. **监控信号**：查看交互触发、选择分布、完成率、退出时点与结局到达。
4. **解释行为**：区分玩家没有看见、看见但没理解、理解但不愿选、选择后反馈不足四类问题。
5. **做下一轮动作**：调整提示、代价、回报、事件位置或叙事承接，而非只提高奖励数值。
