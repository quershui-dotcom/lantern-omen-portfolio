# P12 Summary｜系统策划与产品运营能力总结

> 收束《灯谶》在系统策划与产品运营方向上的项目能力

---

## 我做的不是单一数值方案

《灯谶》的推进路径是：

**题材与用户体验 → 核心循环 → 可配置系统 → 内容运营入口 → 行为验证 → 版本迭代 → 公开试玩交付**

数值仍是系统的一部分，但不再是展示中心。展示重点转为：玩家为何进入、如何理解目标、在哪里做选择、选择如何留下后果，以及后续版本怎样扩展这些内容。

---

## 能力地图

| 能力域 | 《灯谶》中的落地 | 可迁移能力 |
| --- | --- | --- |
| 核心系统设计 | 灯界、遗影证词、遗愿与命簿结局构成一条可回收的系统链 | 从玩家动机拆解目标、规则、资源、反馈与状态 |
| 内容与叙事运营 | 封河夜、割名令、命簿焚城按时间线进入三次祭灯互动 | 将世界观转为分期内容、人物档案、活动主题与传播素材 |
| 版本规划 | 将基础交互、人物支线、档案内容、终局收束拆分为连续版本主题 | 围绕玩家路径排定内容优先级与验证顺序 |
| 体验诊断 | 定位 E 键失效、祭灯遮挡、技能表现不可见等问题并完成回归 | 用现象-根因-修复-验证形成问题闭环 |
| 指标与实验 | 定义祭灯发现、交互成功、遗愿分布、结局到达等系统健康信号 | 把体验问题转译为可观察、可行动的运营问题 |
| 上线交付 | GitHub Pages 外网发布、完整作品集保留、试玩持续迭代 | 从设计稿走到可访问、可验证、可分享的产品结果 |

## 职位表达

《灯谶》证明的不是"我能写一套参数"，而是我能够围绕玩家体验设计系统、组织内容、识别行为信号、推动版本迭代，并将成果交付为可公开试玩的产品案例。这也是我希望在系统策划、游戏产品运营与内容运营岗位继续深化的能力。
